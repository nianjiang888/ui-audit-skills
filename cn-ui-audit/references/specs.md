# 中文 UI/产品审计 · 规范与判定基准

本文件是 cn-ui-audit 的"依据库"。审计时按场景调取对应段落对照，不要凭感觉。所有数值以各平台官方文档最新版为准，过期请更新此处。

---

## 1. 微信小程序设计规范（场景：小程序）

- **基准单位 rpx**：750rpx = 屏幕宽度。设计稿按 750 宽出，自动适配各机型。
- **导航栏**：顶部高度含状态栏，标准导航栏高度约 88rpx（不含状态栏）；胶囊按钮固定在右上角，尺寸约 87×32px（逻辑像素），左右间距约 7px。自定义导航需避让胶囊区域，不能在胶囊下放可点元素。
- **tabBar**：底部最多 5 个、最少 2 个，图标建议 81×81px（@2x 约 162），文字 20rpx 左右。tabBar 数量奇数更稳（3 或 5）。
- **页面层级**：小程序是单层导航（非原生多窗），避免用"弹窗套弹窗"模拟多窗口；需要多步用分段或页面跳转。
- **字体**：小程序默认字体随系统（iOS 苹方 / Android 思源/系统默认）。不要用开发者的"艺术字体"做正文，可读性优先。
- **按钮**：主操作按钮宽度建议 ≥ 表单宽度的 80%，高度 ≥ 88rpx；禁用态要明显（灰度 + 不可点反馈）。
- **触控目标**：可点元素最小 88rpx（约 44pt），间距 ≥ 16rpx，避免误触。
- **常见扣分点**：自定义导航遮挡胶囊、tabBar 超过 5 个、按钮高度 < 88rpx、正文用衬线艺术字、深色模式未适配（小程序需自行处理 darkmode）。

## 2. Ant Design 规范（场景：中后台 / Web 管理界面）

- **栅格基准**：8px 网格。间距阶梯建议 8 / 16 / 24 / 32 / 40 / 48。
- **主色**：#1677ff（v5 默认蓝）。功能色：成功 #52c41a、警告 #faad14、错误 #ff4d4f、链接 #1677ff。
- **圆角层级**：小组件 2px、卡片/弹窗 4–8px、大容器 ≤ 8px。不要全站统一大圆角。
- **字号阶梯**：12 / 14 / 16 / 20 / 24 / 30 / 38（px）。正文 14，次级 12，标题 16–20。
- **行高**：正文 1.5–1.571，标题 1.3 左右。
- **字体族**：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif`。中文优先 PingFang SC / 微软雅黑。
- **对比度**：正文文字与背景 ≥ 4.5:1（WCAG AA）。
- **常见扣分点**：间距不按 8 倍数、主色自行改成高饱和紫、表格行高过密（< 40px）、错误提示只用颜色不配文字（色盲友好）。

## 3. iOS 人机界面指南 HIG（场景：iOS App）

- **安全区（Safe Area）**：内容避开刘海、圆角、底部 Home Indicator。顶部状态栏 + 导航栏约 44pt，底部标签栏 49pt。
- **触控目标**：最小 44×44pt（约 88rpx）。
- **Dynamic Type**：支持系统字号缩放，正文用 `UIFontTextStyle`，不要写死 px。
- **字号阶梯**：大标题 34pt、标题 1 28、标题 2 22、标题 3 20、正文 17、副标题 15、脚注 13、说明 12。
- **系统色**：用系统语义色（label / secondaryLabel / systemBlue 等），暗色模式自动适配，不要写死 #000/#fff。
- **深色模式**：所有界面必须提供暗色变体，对比度与层级在双模式下一致。
- **常见扣分点**：忽略安全区导致内容被刘海切、触控目标 < 44pt、写死字号不支持缩放、暗色模式缺失或对比度塌。

## 4. 各平台投稿画幅（场景：内容平台投稿图 / 视频封面）

数值为常用基线，以平台最新规范为准。

| 平台 | 竖屏/主画幅 | 横屏/次画幅 | 备注 |
|---|---|---|---|
| 抖音 | 9:16（1080×1920） | 16:9（1920×1080） | 图文封面常用 3:4 |
| 小红书 | 3:4（1242×1660） | 1:1（1080×1080） | 竖图流量优于横图 |
| 视频号 | 9:16（1080×1920） | 16:9 | 同抖音基调 |
| B站 | 16:9（1920×1080） | 竖屏 9:16 | 投稿封面 1146×717 左右 |
| 公众号 | 封面 16:9（900×383 或 2.35:1 大图） | 次条 1:1（200×200 缩略） | 头图 2.35:1 更醒目 |
| 微博 | 1:1（1080×1080） | 9:16 / 4:3 | 九宫格为 1:1 |

- 画幅错了会被平台裁切，关键信息（人脸、标题、Logo）必须留在安全区（中心 80% 区域）。
- 封面标题字号在缩略尺寸下仍要可读，不要用细体小字。

## 5. 中文排版规范

- **标点全角**：中文标点用全角（，。、；：""''《》（））。禁止中英文标点混用（如中文句里夹半角逗号、英文括号）。
- **禁止长破折号（——）滥用**：中文长破折号是明显的 AI 生成痕迹，标题、按钮、正文里能改短句就改短句，或换逗号。
- **字号层级**：正文 ≥ 14px（移动端）/ 12px（后台密集表可放宽到 12 但需保证对比度）；层级靠字号 + 字重 + 颜色，不靠单一手段。
- **行高**：中文正文 1.5–1.8；标题 1.3 左右。行高 < 1.4 中文会挤。
- **字间距 / 段间距**：标题可微加字距；段落间留白 ≥ 行高的 0.5 倍，不要用空行堆。
- **孤字寡行**：避免行尾单字成行、段落末孤行；长文本用 `text-align: justify` 要谨慎（中英文混排易留空洞）。
- **中文不斜体**：italic 对中文无意义（只是伪斜），强调用字重 / 颜色 / 下划线。
- **数字与单位**：中文里数字用半角，单位与数字间留半角空格（如 `750 rpx`）；温度、百分比按语境。

## 6. 反 AI 味文案清单（逐项体检）

| 类型 | 典型表现 | 整改方向 |
|---|---|---|
| 破折号滥用 | 标题"高效协作——让团队更敏捷" | 拆成两句 / 换逗号 / 直接说 |
| 空话词 | 赋能、一站式、闭环、拉通、对齐、抓手、降本增效、打通最后一公里、组合拳 | 换成具体动作（"把三个系统数据接进来"） |
| 虚假精确数字 | "效率提升 92%""4.1× 增长""48k 用户" | 无来源就删，有来源标出处 |
| emoji 装饰 | 用 ✅⭐🚀💡 当格式符号、列表前缀 | 去掉或换成文字/图标组件 |
| 中英文标点混用 | 中文句里夹 `,` `()` `"` | 统一全角 |
| 排比工整病 | 三个小标题结构长度高度一致、全用四字 | 故意打破平行，长短参差 |
| 总结腔 | "综上所述""值得注意的是""毋庸置疑" | 直接说结论 |
| 星级评分 | 用 ★★★★★ 量化主观 | 自然语言描述 |
| 占位名 | John Doe、张三经理、某用户 | 真实感中文名或留空 |

## 7. 审计评分卡（严重度 + 判定阈值）

### 可访问性硬指标（P0 触发线）
- 正文对比度 < 4.5:1（WCAG AA）→ P0
- 大字（≥18pt 或 ≥14pt 粗体）对比度 < 3:1 → P0
- 触控目标 < 44pt（小程序 < 88rpx）→ P0
- 信息只靠颜色传达（红绿不分）→ P1（色盲友好：加文字/图标）

### 视觉层级（P1 触发线）
- 一屏内焦点超过 3 个且无主次 → P1
- 三等分 identical 卡片 → P1
- 卡片套卡片（nested cards）→ P1
- 标题与正文字号差 < 2 级 → P2

### 色彩与对比（P1 触发线）
- 纯黑 #000 / 纯白 #fff 直接使用 → P2
- 彩色背景叠灰色文字 → P1
- 饱和度失控（主色饱和 > 90% 且大面积）→ P2
- 暗色/亮色模式对比度或层级不一致 → P1

### 间距与节奏（P2 触发线）
- 间距不落在 8 倍数栅格（后台/Web）→ P2
- 留白过多（信息密度过低，营销页可接受）或过密 → P2
- 行高 < 1.4（中文）→ P2

### 动效与体验（P2 触发线）
- 动效无目的（纯装饰、说不清理由）→ P2
- 弹性/弹跳缓动（bounce/elastic）→ P1
- 未尊重 `prefers-reduced-motion` → P2
- 用 width/height 做动画（非硬件加速）→ P2

### 文案与排版（见第 6 节）
- 破折号滥用、空话词、虚假数字、emoji 装饰、中英文标点混用 → 按出现数量定 P1（大量）/ P2（少量）

### 场景规范偏离
- 小程序：遮挡胶囊、tabBar > 5、按钮 < 88rpx → P1
- 投稿图：画幅错、关键信息在裁切区外 → P1
- iOS：忽略安全区、触控 < 44pt、无暗色模式 → P0/P1
- Ant Design：间距不按 8 倍数、主色乱改 → P2

## 8. 审计流程自检（输出前过一遍）

1. 是否标了场景（第 0 步）？没标就是不及格。
2. 每条问题是否有：位置 + 依据 + 整改？缺一项退回。
3. 严重度是否按 P0→P3 排序？P0 是不是真的"读不清/点不到/误导"级？
4. 反 AI 味体检是否单独出了？破折号/空话词/虚假数字有没有漏。
5. 双模式一致性查了没有？
6. 去 AI 味：有没有"综上所述""值得注意的是"？有就删。
