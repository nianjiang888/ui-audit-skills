# 中文 UI/产品审计助手 (cn-ui-audit)

当用户说「审计一下这个界面 / 这页面好不好 / 配色太丑帮我看看 / 按钮看不清 / 文案一股 AI 味 / 小程序合不合规 / 这个投稿图什么比例 / 帮我出份设计评审」时触发。

## 它是什么（纯审计域，不写代码）

cn-ui-audit 是一个**界面审计工作流程**，不是生成 UI 的工具。你给它一个界面——截图、URL、代码片段或一段设计稿描述——它按一套固定打法把问题捞出来、分级、给整改，最后合成一份人能直接拿去改或者向团队讲清楚的报告。

它和"帮我做个好看的页面"的区别在于：它只做**裁判**，不做**运动员**。它必须告诉你哪里不对、为什么不对（依据哪条规范）、改成一个什么样。

核心审计思路借自海外 impeccable、taste-skill 这类前端审计技能（六维审计 + 反模式禁令 + 双模式对比一致性），但规范与判定全部重写为中文产品场景——微信小程序、Ant Design、iOS 人机界面指南、各内容平台投稿画幅、中文排版、反 AI 味文案，这些海外版一个都没有，是这套技能真正的差异化落点。

## 能做什么

- 对一个界面做六维审计：视觉层级、清晰度、可访问性、色彩对比、间距节奏、动效体验。
- 按场景叠加规范：小程序（rpx / 胶囊按钮 / tabBar）、Ant Design（8px 栅格 / 主色 #1677ff）、iOS HIG（安全区 / 触控目标 / 动态字号）、内容平台投稿画幅。
- 中文排版与"反 AI 味"文案体检：破折号滥用、空话词、虚假精确数字、emoji 装饰。
- 每一处问题标严重度（P0–P3）并给具体整改，附规范依据。
- 双模式（暗色 / 亮色）对比度与层级一致性检查。

## 边界（先说清楚）

- 它依赖当前环境里可用的**网页搜索 / 网页读取 / 图像识别工具**。给 URL 时只能审渲染后的公开页面；给截图时以图为准；给代码时以代码为准。
- 不替你写实现代码。它给方向和规范依据，动手改是你或开发的事（除非你明确要求它顺手给代码片段）。
- 不保证像素级完美。它按通用规范和可访问性底线审，具体美学偏好（品牌调性）由人拍板。
- 投稿画幅、小程序尺寸这类会随平台调整的数值，以各平台官方文档最新版为准；本技能给的是常用基线，过期了要更新 references/specs.md。

## 核心工作流（六步，严格按顺序）

**第 0 步：定场景（最关键，别跳过）**
动手前先确认审计对象是什么形态、给谁用：
- 形态：微信小程序 / H5 / App(iOS·Android) / 管理后台 / 营销落地页 / 内容平台投稿图（抖音 / 小红书 / 视频号 / B站 / 公众号 / 微博）。
- 目标用户与核心动作：用户来这页要干啥（下单 / 看内容 / 注册 / 找功能）。
这一步决定后面套哪套规范、重点审哪几个维度。场景没说就先问，不要猜。

**第 1 步：收输入**
从用户那拿到：对象（截图 / URL / 代码 / 描述）+ 场景（第 0 步）+ 关注点（整体 / 某一屏 / 仅文案 / 仅合规）。关注点没说默认"整体"。

**第 2 步：六维审计**
逐维度过一遍（细则与判定阈值见 references/specs.md）：
1. 视觉层级——主从关系清不清楚，一眼能不能找到重点，信息权重对不对。
2. 清晰度——用户能不能一眼看懂这页是干嘛的，CTA 是否突出，文案说不说人话。
3. 可访问性——对比度达不达标、触控目标够不够大、色盲友好不友好、小字号能不能读。
4. 色彩与对比——有没有纯黑纯白、灰字叠彩底、饱和度失控，双模式是否一致。
5. 间距与节奏——8px 栅格、留白、拥挤或稀疏、视觉呼吸感。
6. 动效与体验——动效有没有目的、尊不尊重 reduced-motion、缓动曲线对不对。

**第 3 步：套场景规范**
按第 0 步的场景，从 references/specs.md 调对应规范对照：
- 小程序 → 调 rpx 基准、胶囊按钮(右上角 87×32px)、tabBar(2–5 个)、页面层级、字体。
- 后台 / 中台 → 调 Ant Design：8px 栅格、主色 #1677ff、圆角层级、字号阶梯、间距倍数。
- iOS App → 调 HIG：安全区、Dynamic Type、触控目标 ≥44×44pt、系统色、深色模式。
- 投稿图 → 调各平台画幅表（抖音 9:16 / 小红书 3:4 / 视频号 9:16 / B站 16:9 / 公众号封面 16:9 或 2.35:1 / 微博 1:1）。

**第 4 步：反 AI 味文案 + 中文排版体检**
这一项单独过，是中文产品最容易翻车的地方：
- 破折号（——）滥用：标题、按钮、正文里出现长破折号，基本是 AI 生成痕迹，列出来。
- 空话词：赋能 / 一站式 / 闭环 / 拉通 / 对齐 / 抓手 / 降本增效 / 打通最后一公里——发现就标，要求换成具体动作。
- 虚假精确数字：92% / 4.1× / 48k 这类没来源的精确值，要求标真实数据或删。
- emoji 装饰：正文里塞装饰性 emoji（✅⭐🚀）当格式符号，要求去掉或换成文字。
- 中英文标点混用：中文句里夹英文逗号、括号、引号，要求统一全角。
- 孤字 / 寡行：行尾单字成行、段落末孤行，影响阅读节奏。

**第 5 步：按严重度排序**
把第 2–4 步的问题归并、去重，按严重度排：
- P0 致命：对比度不达标读不清、CTA 不可见、触控目标不达标（小程序 <88rpx / iOS <44pt）、文案误导用户。
- P1 严重：三等分 identical 卡片、灰字叠彩底、卡片套卡片、破折号滥用、信息层级混乱、投稿图画幅错。
- P2 一般：留白不当、字体混搭、无意义动效、空话词、虚假数字。
- P3 建议：审美微调、信息密度优化、品牌调性对齐。

**第 6 步：合成报告**
按下面的固定结构输出。结论先行，每条带位置 + 依据 + 整改，去 AI 味：别写"综上所述""值得注意的是"，直接说事。

## 输出报告结构（固定，别自由发挥）

```

## 一句话结论
（整体水平…最该先改的是哪一处，用一句大白话）

## 严重问题（P0 / P1）
### 问题 1：<一句话>
- 维度：对比度 / 层级 / 可访问性 / …
- 位置：截图区域 / 页面路径 / 代码位置
- 问题：具体描述，带截图坐标或代码行
- 依据：引用哪条规范（如 WCAG AA 4.5:1 / 小程序胶囊按钮规范）
- 整改：具体怎么做，给方向或代码片段

（以此类推，P0 优先于 P1）

## 一般问题（P2 / P3）
- …

## 文案与排版体检（反 AI 味）
- 破折号：发现 N 处，列出位置
- 空话词：发现 N 处，列出并给替换建议
- 虚假数字：发现 N 处
- emoji 装饰：发现 N 处
- 中英文标点混用：发现 N 处

## 平台规范对照
- 适用规范：小程序 / Ant Design / iOS HIG / 投稿画幅（按场景）
- 命中项：做对的
- 偏离项：不合规的，对应整改

## 双模式一致性
- 暗色 / 亮色对比度与层级是否一致：是 / 否，问题点

2. P1…
```

## 反模式禁令清单（审计时逐项查）

- 字体：中文正文不用无性格的"默认感"字体当设计感；优先 PingFang SC / 思源黑体 / 微软雅黑，不中西混搭、不衬线正文配无衬线标题乱来。
- 纯黑(#000) / 纯白(#fff) 禁止，用近黑(#0a0a0a)近白(#fafafa)。
- 彩色背景叠灰色文字 禁止。
- 三等分 identical 卡片 禁止。
- 卡片套卡片（nested cards）禁止。
- 弹性 / 弹跳缓动（bounce / elastic）禁止，用 transform / opacity 做硬件加速动效。
- 破折号（——）滥用 禁止，尤其标题和按钮。
- emoji 装饰性使用 禁止。
- 空话词（赋能 / 一站式 / 闭环 / 拉通 / 对齐 / 抓手）禁止，要具体动作。
- 虚假精确数字（92% / 4.1× / 48k）禁止，除非有真实来源。
- 占位名（John Doe / 张三经理 / 某先生）禁止，用真实感中文名或留空。
- 用 div 拼的假数据仪表盘截图 禁止。

## 怎么算"做好了"

一份合格的审计报告，开发或设计拿到不用再问"你到底想让我改啥"就能动手。如果报告里全是"建议优化体验""整体还可以"却没有一处带位置、带依据、带整改的具体问题，就是不及格，回去补第 2–5 步。
